# 教学文档生产系统（MemoEdu）

面向数学教师的教学讲义自动生产系统：把一个**经过校验的题库**，按学段、教材、知识点板块和难度组织起来，
按老师给定的班级进度和选题要求，渲染成可以直接发给学生的讲义文档（Word）。

本仓库**不含任何题目数据**，只含结构、逻辑、规格与验证机制。

## 它想解决什么问题

老师现在的做法是：手工找题、手工判断难度、手工排版，一份分层讲义要做一两个小时。
这个系统想把这件事变成"提一个受控请求 → 系统按门禁选题 → 出文档 → 记录这份文档实际用了哪些题"，
并且让"某道题在哪个班用过、效果如何"变成可以累积的数据。

## 目前能做到什么

- 题库的数据结构、来源证据链、教材与知识点映射、审批门禁：已定义并有实现与测试。
- **从题库按选题计划渲染出一份套好模板的讲义文档：这条路径已经实际跑通过**（模板由老师准备，系统负责填题）。
- 一整套"不达标就阻塞并报告，绝不跨教材/跨学段/跨知识点硬凑题"的 fail-closed 门禁。
- 不依赖任何外部服务的离线验证入口：`python run_offline_regression.py`。

## 目前卡在哪里（这也是我开源它的原因）

**唯一真正的卡点是"充实题库"这一步。**

系统的质量取决于题库里有没有足够多、且带有可靠难度与知识点标注的真实题目。我原本的做法是：
从自己已付费的题库服务上把整卷下载下来，再转换成题库内容。这条路我花了一个多月，没有走通——
剩下的障碍不是转换逻辑，而是自动化下载本身受站点前端与授权状态制约，个人无法稳定推进。

替代路径我也想清楚了：
- **买/拿别人做好的题库**：需要授权，而且费用对个人来说不划算；同时它必须是可核验来源，不能是又一份脏数据。
- **让 AI 直接生成初中几何题及其配图**：以现在的工具还做不到可靠——图形与条件不一致、答案不可复核，这类错误在教学场景里是不可接受的。

所以我选择停下来，把它开源。**如果你手上有"可授权、可核验、带知识点与难度标注的题目数据"来源，或者知道更好的获取方式，
这个项目立刻就能往前走；缺的正是这一块。**

## 仓库里**没有**的东西（发布前已做处理）

- 任何题目原文、答案、解析、试卷截图；
- 任何**含题目原文**的数据库文件（随仓库走的样例是去文本版，见下一节）；
- 面向具体题库服务商的自动化下载与目录抓取代码（6 个脚本）；
- 2 个文件因其测试夹具本身就是真实考题而未随发布（其覆盖的逻辑由其余测试继续守住）；
- 内部工作单、完成报告与逐次执行记录（约百份过程文档，只反映当时的推进状态，不具参考价值）；
- 任何 API Key、Cookie、Token、密码——本项目从未把这些写入版本库。

保留的文档里，服务商名称与标识已统一替换为中性占位（`extsrc` / 外部付费题库平台），本地绝对路径已替换为 `<local-path>`。
另有一部分测试以开发库快照为夹具（见 `run_offline_regression.py` 中的 `BANK_DEPENDENT_MODULES`），它们需要你自建题库后才能运行，
在开源版里会被明确报告为跳过，而不是假装通过。

## 想在本地跑起来

1. Python 3.9+（开发时用的是 3.13）。渲染 Word 需要本机安装 Word 或使用 LibreOffice 路线，其余功能不需要外部服务。
2. 建一个空题库结构：`python tools/bootstrap_isolated_schema.py`（生成隔离的开发库，不含数据）。
3. 验证：`python run_offline_regression.py`。
4. 填题：需要你**自己拥有授权**的题目来源。系统的来源证据链要求每题可追溯到原始文档版本，
   不接受来历不明的题目文本。

## 仓库里带了一份"去文本版真实题库"

`data/sample/teaching_docs_sample_bank.db.gz` 不是空壳演示，它是一个真实推进过的项目数据库（初中几何那一个班级的实际状态），
只是**把不属于我的那部分文字去掉了**。它让你看到"一个填到 3605 道题的库长什么样"，而不必猜。
解包后 187.7 MB / 打包 50.6 MB（GitHub 拒绝单个超过 100 MB 的文件，所以压缩随仓库走）。

- **保留**：87 张表的完整结构、248,382 行记录、每道题的学段/年级/题型/难度/质量与审批状态、
  来源文档登记与页码、知识点映射与审批链、26,451 条证据记录、以及**所有内容哈希**
  （哈希还原不出原文，但你能看清"来源可核验"是怎么落地的）。
- 另有一份 0.5 MB 的小库 `p1-2f_baseline_stripped.db.gz`（65 张表、7,330 行），它是迁移与溯源测试用的起始夹具形状。
- **去掉了**：题干、选项文本、答案、解析、整页原文块、学生成品文本、证据文本片段——这些是从付费平台取得的
  原题文字，我没有权利替原作者发行。去掉的位置留了 `<text-removed>` 标记，一眼能看出该填什么。
  变更台账 `content_change_ledger` 的 24 万行数据不保留（每一格都是上面那些文字的副本），表结构保留。
- **去标识化**：来源文档的文件名与本地路径换成 `<source>/item-0001.docx` 这类稳定编号（同一文档跨表编号一致，
  所以溯源链仍然可验证，但看不出文件名）。
- **有意保留的中文**：教材名与章节名（`curriculum_nodes.name` 178 条、`textbooks.name` 29 条）——
  那是"第二章 不等式与不等式组"这类公开教材目录，不是考题内容，而它正是整套标注体系的地基。

逐列的处理记录与判断理由在 `data/sample/SANITIZATION_MANIFEST.json`。

`python tools/materialize_sample_bank.py` 会把这两个样例解包到测试期望的夹具路径（都写在 `.gitignore` 忽略的
`data/dev/` 下面，不会污染仓库）。加 `--full` 会额外解出那个 188 MB 的规模参照库。

**但默认门禁仍然按名字跳过 30 个模块**，理由写在 `run_offline_regression.py` 里：这些模块会重新计算并比对题目文字的
内容哈希，而文字正是被删掉的部分。我实测过给上去文本夹具也不能让它们通过（71 项里 1 项失败、28 项错误），
所以与其让一个"看起来能跑其实跑不过"的开关存在，不如明确跳过并说明原因。
你自己有授权文字、把题目填回去之后，把这些模块从跳过名单里移出来即可。

## 希望得到的帮助（按价值排序）

1. **合规的题目数据来源**：教材配套、可授权、带知识点与难度标签的题库接口或数据集。
2. **几何题图形生成与图文一致性校验**：能判定"图与条件是否一致"的可复核方法。
3. **难度与知识点标注质量**：不依赖人工穷举的标注与抽检方案。
4. 把 legacy 根目录模块提升到 `docs/governance/MATURITY_AND_WORKTREE_REGISTER.md` 里定义的正式层级。

## 参与方式

改动走"规格 → 架构契约 → 工作单 → 实现 → 完成报告"的顺序，见 `CONTRIBUTING.md`。
